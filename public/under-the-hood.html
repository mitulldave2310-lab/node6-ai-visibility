Overview

A research agent and an enquiry desk, with every claim checked.

You type a company. Three Claude calls research it, decide the fit and write a first message. Code then checks every quote against its source and decides what a person must review. Inbound enquiries run through the same engine and wait for one-tap approval in n8n.

What runs on one click

  1. 13 website checks, scored by code
  2. 3 Claude calls: Sonnet research, Haiku decision, Sonnet draft
  3. Up to 3 web searches, only cited text kept
  4. Every quote matched word for word to its source
  5. 7 copy rules on the draft, one automatic rewrite

What a person still decides

  • Every outbound email: the desk writes drafts and never sends them
  • Every enquiry reply: n8n emails an approval card first
  • Any company where no quote could be verified
  • Any fit below tier B

Built and tested: 37 automated tests, 33 logged live runs, 1 enquiry tested end to end.

Pipeline

Five steps, timed on real runs.

Bar length is the median time of each step across 27 successful live runs. Web research is the slow part, because it waits on search results.

Why two models

Haiku 5.5 makes a short structured judgment (service, tier, next step) quickly and cheaply. Sonnet 5.5 does the reading and the writing a person will see.

Why Claude doesn't set the score

The website score comes from 13 weighted checks in code, so the same site always gets the same score. Claude explains and decides; it never grades.

    Guardrails

    Rules that Claude can't talk its way past.

    These quotes came back from Claude in the test runs and failed the word-for-word check. The desk showed them as unverified instead of trusting them.

      Routing rules

      • No verified quote at all: a person reviews it
      • Site won't load and no web quote verifies: a person reviews it
      • Draft only for tier A or B
      • No service fits: disqualified, no draft
      • Enquiries are never dropped automatically

      Copy check on every draft

      • Under the word limit
      • No long dashes, no banned sales phrases
      • No placeholders like [Name]
      • Every number must appear in the evidence
      • Must use at least one verified fact
      • Fails once: rewritten automatically. Fails twice: flagged for a person

      Found and fixed in live testing

      No citations
      The newest web search tool filters results through code and returned no citations, so nothing could be verified. Switched to the version that returns cited quotes.
      Good fits held back
      Claude treated unknown budget and headcount figures that differ between sites as "conflicting evidence". One prompt rule fixed it: 4 of 4 tier B companies then got drafts.
      Blocked websites
      Sites that refuse to be read went to manual review even when web quotes verified. The rule now fires only when no web quote verifies.
      Token mismatch
      The enquiry was rejected by n8n until both sides used the same secret. Checked: 403 without it, 200 with it.

      Enquiry automation

      n8n workflow: nothing is sent until a person taps Send.

      The live workflow "node6 Enquiry Desk (Week 6)" has 10 steps. The app posts each researched enquiry to a protected webhook; n8n logs it, emails the approver and waits.

      End-to-end test, 21 Nov

      1. 0s Test enquiry sent from the form (reference E-MWQ39D54)
      2. 31s Claude research, decision and draft done, posted to n8n
      3. Then Logged in Airtable, approval email arrived in the test inbox
      4. Tap Send reply pressed, reply delivered to the enquirer

      Safety on the webhook

      • Header token required: requests without it get 403
      • Form must come from this site, with consent ticked
      • 5 enquiries per 10 minutes per connection
      • Replies sign as node6 Labs; outbound drafts sign as Mitull
